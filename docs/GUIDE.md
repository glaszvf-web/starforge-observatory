## 1. 这是什么

把 DSH 的记忆分层（`~/.dsh/memory/layers/l1-l3.json`）渲染成一座可旋转的三维星图。

三个形态，同一个画面里切：

| 形态 | 看什么 | 实现要点 |
|---|---|---|
| **星团** GALAXY | 59 个记忆分区按**斐波那契球面**铺在空间里，每个分区一团记忆光点 | 真 3D，有前后纵深 |
| **隧道** TUNNEL | 13 个实体门环沿 z 轴排开，相机正对着穿过去，环间跳电 | 不是「曲速线爆射」 |
| **关系网** NETWORK | 分区之间的贝塞尔纤维，紫色流光沿纤维跑 | 像神经传导 |

**数据是真的**：262 条原子 / 59 个分区 / 56 条连接，每次启动从记忆库重建。


## 4. 三个形态怎么实现的（读懂这几处就能改）

### 4.1 配色

两处：

- **界面**：`index.html` 顶部 CSS `:root` 变量（`--accent` / `--accent2` / `--ink` / `--dim` …）
- **3D**：`KIND_COLOR` / `KIND_RGB`（记忆类型配色）+ 场景里散落的 `0xRRGGBB` 字面量

当前四条主线：

| 角色 | 色值 | 用在哪 |
|---|---|---|
| 背景 | `#07050e` 紫黑 | 整页底、`FogExp2` |
| 主色 | `#5eeaff` 青蓝 | 光流、门环、连线、边框 |
| 副色 | `#b78cff` 紫 | 电弧、流光、门环交替色 |
| 暖色 | `#ffc46b` 金 | **数值、角标、进度条末端、分区计数** |

**暖色这一条不能省。** 早期整套只有蓝和黑，冷到底、没有焦点 —— 看久了分不清哪里是数据哪里是背景。
把数值做成暖白 `#fff6e8` + 金色光晕、进度条做成青→金渐变，画面才有「数据在发光」的层次。

### 4.2 界面排版

```text
┌── 顶栏：品牌 / 三形态 / 全屏 ····· 原子·CPU·FPS·连接·时钟 ──┐
│ 左栏五张卡              3D 画面                右栏两条表  │
│ 记忆原子·ATOMS                                   分区索引   │
│ 场景层·LAYERS                                    信号分类   │
│ 人格单元·PERSONA                                            │
│ 分区·PARTITIONS                                             │
│ 图谱指纹·HASH                                               │
└── 底栏五块：事件流 / 粒子场 / 记忆总线 / 系统脉搏 / 记忆热力 ──┘
```

左栏是**卡片**不是「竖线 + 数字」：圆角、边框、渐变底、左边一条青线。
数值字号 23px、暖白 + 金色投影；每张卡的进度条是青→金渐变。
改高度时注意别让第五张卡撞到底部操作提示（`top:80px` 起，底栏高 188px）。


### 4.3 电弧（这套的性格所在）

搜 `ARC_COUNT`：

- `arcs[]` 是电弧池（34 条），每条是 `THREE.Line` + 26 段顶点
- `spawnArc(from, to, life, amp)` 取一条空闲的、绑上端点
- `updateArcs(dt)` 每帧重算折线：**中间段抖、两端贴住**（`env = sin(u*PI)`），紫白色
- `fireArcTick(dt)` 负责触发：六成从中心球打出去、四成节点之间对接、两成连锁跳电 `a→b→c`
- 中心球放电时 `coreFlash = 1`，`animate` 里把核心光晕放大 62%、亮度拉满

**调参入口**：想让电更密就减小 `arcTimer`；想更亮就改 `col[o+1]`（绿通道越低越紫）。

### 4.4 门环隧道

搜 `GATE_COUNT`：

```js
const GATE_COUNT = 13;
mesh.position.z = 16 - t * 52;      // 从相机前方 16 一路排到 -36
new THREE.TorusGeometry(3.6, 0.055, 8, 150)
```

- 只在 `mode === 1` 时 `gateGroup.visible = true`
- 每环错相呼吸、慢慢自转（`updateGalaxy` 里）
- 电弧在相邻环之间跳（`fireArcTick` 的隧道分支）
- **隧道模式相机会强制回正**（`updateCamera` 里把 `targetYaw/Pitch` 往 0 收，`targetDist = 11`）——斜着看会散成一堆错开的圆

### 4.5 星团的球面分布

搜 `GOLDEN`：

```js
const GOLDEN = Math.PI * (3 - Math.sqrt(5));
i => { y = 1 - i/(n-1)*2; ring = sqrt(1-y*y); theta = GOLDEN * i; }
```

这是斐波那契球面采样 —— 把 59 个分区均匀铺在一层壳上，从任何角度看都是立体的。
早期用的是「排成一个平面圆环」，所以不管怎么转，画面都是「中间一坨、四周一圈」。

### 4.6 底部四块仪表

`drawSwarm` / `drawRouter` / `drawWave` / `drawHeat`，都是 Canvas 2D 手绘：

- **粒子场**：粒子沿径向持续外流（`(seed + time * speed) % 1`），带拖尾、越远越淡
- **记忆总线**：渐变条 + 沿条跑的流光点 + 末端高光
- **系统脉搏**：CPU 面积填充 + MEM 副线 + 末端光晕 + 横向扫描线
- **记忆热力**：扫描列逐列点亮 + 高值格外晕 + 四角标记

## 5. 踩过的坑（一条都别重踩）

| # | 坑 | 症状 | 解法 |
|---|---|---|---|
| 1 | **`mode` 的 TDZ** | 整个页面白屏，`m-atoms` 显示 `--` | `let mode` 声明在 1390 行，`updateCamera(0)` 在 1135 行就调用它 —— 撞暂时性死区。**而且 `typeof` 对 TDZ 变量一样抛错**，兜不住，只能 `try/catch` |
| 2 | 门环保留太远/太细 | 隧道模式看着跟没做一样 | `z=-58` + `tube=0.03` → 投影不到 1px。拉近到 `16~-36`、管径提到 `0.055` |
| 3 | 隧道模式相机不归正 | 门环散成错开的圆，不成隧道 | 模式切到隧道时把 yaw/pitch 往 0 收 |
| 4 | **`PointsMaterial` 默认画方块** | 满屏小方片在飘，看着像网格不像粒子 | `Points` 不给贴图就是正方形。两处（`stars` / `diskMat`）都必须挂 `map: GLOW, alphaTest: 0.01`。这是「这不是粒子吗」那个问题的根因 |
| 5 | 曲速线太密 | 把左右栏 KPI、底部日志全盖掉 | 星团/关系网压到 `0.05 + tunnel*0.9`，隧道模式直接 `0.05` |
| 6 | 删掉 `FogExp2` | 画面变成平的，没有远近 | 雾是纵深的来源，别的参数怎么调都补不回来 |
| 7 | 电弧颜色跟背景太像 | 电看不清，混在曲速线里 | 背景青蓝 → 电弧用紫白，绿通道压到 0.58 |
| 8 | 假 bloom 用 `source-over` | 中心压出一圈不透光的灰雾 | 必须 `lighter` 加色 |
| 9 | `Get-NetTCPConnection` 判端口 | 服务明明在跑却报「端口空闲」 | 本机这条命令对 8900 返回空，判断端口一律用 TCP 探测或 `curl /api/health` |
| 10 | PowerShell 5.1 读无 BOM 的 UTF-8 | 脚本双击毫无反应、不报错 | `.ps1` 正文保持纯 ASCII，或者写 UTF-8 **带 BOM** |
| 11 | `smoothstep(edge0, edge1, x)` 边界反序 | 多数 GPU 能用，换块卡可能翻 | 规范里 `edge0 >= edge1` 是未定义，一律写 `1.0 - smoothstep(小, 大, x)` |

## 6. 常见改动怎么做

**加一个新的记忆类型**：`build-graph.mjs` 的 `KIND_MAP` 加映射 → `index.html` 的 `KIND_COLOR` / `KIND_RGB` / `KIND_CN` 各加一行。

**让电弧更密/更亮**：`ARC_COUNT` 加大、`fireArcTick` 里的 `arcTimer` 减小、`updateArcs` 里的 `col` 调亮。

**改分区布局**：`buildGalaxy` 里 `nodes.forEach` 那段，球面公式换成螺旋/分层都行，只要给每个 node 一个 `pos`。

**换配色**：CSS `:root` 六个变量 + `KIND_*` 两张表 + 场景里的 `0x` 字面量，一起换，别只换一半。

**加第四个形态**：`setMode` 里扩 `data-mode`、`updateGalaxy` 里加一组透明度目标、`fireArcTick` 里加分支。

## 10. 2026-11-07 · 从 HALOFLUX 拆解换来的三处改造

读 `Ryder191/haloflux`（纯 Canvas 2D，93KB 单文件）之后做的三件事。全都只碰表现层，数据管线一根线没动。

### 10.1 节拍包络（效果最大）

原来核心、光晕、星云各有各的正弦：1.3 / 2.1 / 1.7 / 2.3 / 0.22。五个频率一辈子碰不到一起，读起来像一堆零件各自呼吸。

现在全场认一个 `beatEnv = exp(-sinceBeat * 4.5)`，拍点表故意不均匀：

```js
const BEAT_PATTERN = [0.5, 0.25, 0.25, 0.5, 0.5, 0.75, 0.25, 0.25, 0.25, 1.0];
```

`animate()` 开头先调 `updateBeat(dt)`，然后把这些量都乘上 `beatEnv`：核心 scale / opacity、横向光晕 scale、纵向光晕 opacity、星云 opacity、环线 rotation。原来的正弦留着当底噪，`beatEnv` 叠在上面做脉冲。

实测一秒约 2.5 拍，`beat` 在 0→1→0.2 之间来回，帧率没掉。（这个频率后来被判定太急，见 10.5。）

### 10.2 电弧从单线改成一束

WebGL 的 `lineWidth` 恒等于 1px，单条 Line 做不出粗细。改成编束：

```js
const ARC_STRANDS = 3;
const ARC_ALPHA = [1, 0.34, 0.15];   // 中间实、两边虚
```

每条 strand 沿 `_p1/_p2` 偏移 `a.amp * len * 0.022 * side`，抖动相位用 `skew = k * 3.1` 错开，横截面自然有柔边。34 束 × 3 条 = 102 个 Line，帧率 21~23，跟原来持平。

### 10.3 修掉一个从没生效过的暗角

`.vignette` 原本写着 `mix-blend-mode: screen`。黑色在 screen 混合下等于透明，所以那个 `radial-gradient` 暗角从上线起就没起过作用，屏幕上只剩一条横纹在发光。

改回正常混合以后外围真的沉下去。横纹拆成独立的 `.scanlines` 层，那层保留 screen。

### 10.4 试过但没成的一条

haloflux 的构图是「圆心留在画框外」，巨物感很强。搬到星炬不成立：

- 星炬是三栏布局（左 KPI / 中视觉 / 右索引），中间那块的画框本来就被左右夹住了
- 注视点外推 3.2 单位之后，3D 文字标签跟着飘进左栏，把 KPI 卡糊了
- 退一步想用「放大」换体量：机位 25→19，曲速线和标签一起放大，画面反而更乱

**构图手法得跟着布局走。** haloflux 的画框是整个屏幕，星炬的画框只有中间那一块，两套画框套不了一样的构图法。

### 10.5 第二轮调律（反馈「有律动在闪，但感觉不好」之后）

节拍是有了，但整块屏幕在做亮度波动，看久了累。拆出四层原因：

1. **频率太高** —— 2.5 Hz 眼睛跟得上但会累，`BEAT_SCALE = 1.55` 放到 1.6 Hz
2. **幅度太大** —— 核心一拍涨 72%，压到 30%，从「抽搐」变回「鼓一下」
3. **全场同相（主因）** —— 所有元素共用一个包络，一起亮一起暗。拆成三层延迟：

```js
beatEnv  = Math.exp(-sinceBeat * 3.4);                             // 核心，最急
beatGlow = sinceBeat < 0.08 ? 0 : Math.exp(-(sinceBeat - 0.08) * 3.4); // 光晕，晚 80ms
beatHalo = sinceBeat < 0.17 ? 0 : Math.exp(-(sinceBeat - 0.17) * 2.8); // 星云，晚 170ms
```

波从中心往外推，读起来是扩散。

4. **电弧每帧纯随机取 opacity** —— 这个坑是自己上一轮埋的：一束变三条之后，十几个材质同时在跳，满屏乱闪。改成慢正弦打底：

```js
const flick = 0.66 + 0.20 * Math.sin(a.life * 48 + k * 2.3 + a.seed) + Math.random() * 0.10;
st.mat.opacity = fade * flick * ARC_ALPHA[k];
```

堆料走速度和位移，亮度一分不加：

- 环上四颗流光沿轨道跑（`beltRunners`），一拍加快 1.6 倍，明暗随方位变化
- 拍点时星流窜一下：`warpRadius += warpSpeed * dt * speedFactor * (1 + beatGlow * 0.9)`
- 拍点必打一道电弧：`onBeat()` 里把 `arcTimer` 清零
- 核心从死白改青白：`coreBall.material.color.setRGB(0.80 + coreFlash * 0.20, 0.94, 1.0)`

**教训：闪的是亮度，活的是位移。** 想让画面有生命感，加速度、加位移、加数量，别加亮度 —— 加亮度是最省事也最伤眼的那条路。
